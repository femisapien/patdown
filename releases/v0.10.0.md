## Effect Decision judge

The default backend now answers `PatdownJudge` through Effect `Decision` / `DecisionModel` and `@effect/ai-typesafe`. Yes/no is a probability decision. FAIL-only evidence location is classify. `PatdownJudge`, the cutoff, rule sources, and output are unchanged.

TypeSafe env vars still configure this backend: `TYPESAFE_API_KEY`, optional `TYPESAFE_BASE_URL` (origin, default `https://api.typesafe.ai`), optional `TYPESAFE_DEFAULT_MODEL` (default `jev-latest`). Listing rules still does not need a key.

Provider failures print as `patdown: TypeSafe HTTP …` and still avoid echoing response bodies. A token-limit rejection looks like:

```text
patdown: TypeSafe HTTP 400: model token limit exceeded; shorten the question/input or split it into smaller requests; code: max_tokens_exceeded; input UTF-8 bytes: 97536; request ID: req_...
```

The old `jev: System One HTTP …` prefix is gone. Scripts that grepped that string need the new prefix.

## Effect 4.0.0-rc.116

The workspace pins Effect `4.0.0-rc.116` (was `4.0.0-rc.112`) and Vitest 5 to match `@effect/vitest`. Custom rule adapters and judge layers must use the same Effect rc. Prerelease Effect is not a stable plugin ABI.

## @patdown/jev

Removed. The CLI no longer ships a private TypeSafe HttpClient. Existing `@patdown/jev` installs stay on npm at their last version; this tag does not publish a replacement.

## Distribution

Requires Node.js >=22.22.2. Published as `patdown`, `@patdown/rules`, `@patdown/pi`, `@patdown/claude`, and `@patdown/packs`. The same git tag is what consumers pin for the composite action.
